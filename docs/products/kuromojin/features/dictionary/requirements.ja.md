# 辞書

[English](requirements.md)

## この文書について

辞書の機能は、解析が使う辞書を見つけ、すべての呼び出し元のために一度だけ読み込みます。
Node.js では、呼び出し元は何もする必要がありません。kuromojin のパッケージに含まれる辞書が使われます。
Vite や webpack のように、モジュールが指定するファイルをコピーするバンドラーでビルドするページでも、設定なしでパッケージの辞書が使われます。
それ以外のブラウザの構成では、ページが辞書の URL を kuromojin に伝えます。
親の Product は [kuromojin](../../product.ja.md) です。

### 範囲

- 呼び出し元が辞書を指定しないときに、どの辞書を使うか
- 呼び出し元やページが、辞書の別の場所をどう選ぶか
- どの形式の辞書を、どこで読み込めるか
- 辞書をプロセスごとに一度だけ読み込むこと
- 辞書を読み込めないときに何が起きるか
- パッケージの辞書のサイズ

### 範囲外

- 解析が返すトークン。[トークン化](../tokenization/requirements.ja.md) を参照
- 日付でより新しい辞書を選ぶこと。[辞書のバージョン](../dictionary-versions/requirements.ja.md) を参照
- 利用者が辞書を作ったり、辞書に単語を追加したりするためのツール
- 読みを持たない辞書。未解決事項を参照

## ユーザーストーリー

### 辞書を設定せずに日本語のルールを使う

Node.js で日本語のルールを実行する書き手として、設定なしで辞書が見つかってほしい。ルールをインストールするだけで使えるようにするためです。

**受け入れ条件：**

シナリオ：Node.js で辞書のパスを指定しないとき、パッケージの辞書が使われる

- Given: npm でインストールした kuromojin があり、`dicPath` オプション、`KUROMOJIN_DIC_PATH`、`globalThis.kuromojin` のどれもない
- When: `getTokenizer` を呼ぶ
- Then: Promise は、kuromojin のパッケージの `dict` ディレクトリにある辞書のファイルを使うトークナイザーで解決する

シナリオ：最初の呼び出しのオプションに辞書のパスがないとき、パッケージの辞書が使われる

- Given: 同じインストールで、辞書がまだ読み込まれていない
- When: テキストと `{ noCacheTokenize: true }` で `tokenize` を呼ぶ
- Then: Promise は、パッケージの辞書で解析した、そのテキストのトークンで解決する

### バンドラーでビルドするページで、辞書を設定せずに日本語のルールを使う

textlint と日本語のルールを使うページを Vite や webpack などのバンドラーでビルドする開発者として、設定なしで辞書が見つかってほしい。Node.js と同じく、ルールをインストールするだけで使えるようにするためです。

**受け入れ条件：**

シナリオ：バンドラーでビルドしたページでは、パッケージの辞書が使われる

- Given: kuromojin を（CommonJS で書かれたルールを通す場合も含めて）使うページを、`new URL(path, import.meta.url)` に対応したバンドラーでビルドし、`dicPath` オプションも `globalThis.kuromojin` もない
- When: ページが `getTokenizer` または `tokenize` を呼ぶ
- Then: ビルドにはパッケージの辞書のファイルのコピーがあり、ページはそのコピーの URL をリクエストし、トークナイザーで解決する

シナリオ：バンドラーでビルドしたページが辞書のパスを指定したとき、そのパスが使われる

- Given: 同じページで、`globalThis.kuromojin.dicPath` または `dicPath` オプションが設定されている
- When: ページが `getTokenizer` を呼ぶ
- Then: 辞書はそのパスからリクエストされ、ビルドのコピーからはリクエストされない

### すべてのルールのために辞書を一度だけ読み込む

多くの日本語のルールを実行する書き手として、辞書は一度だけ読み込んでほしい。1 回の実行で、辞書の時間とメモリをルールごとに払わないようにするためです。

**受け入れ条件：**

シナリオ：多くの呼び出し元が同時にトークナイザーを求めたとき、辞書は一度だけ読み込まれる

- Given: 辞書がまだ読み込まれていない
- When: 最初の呼び出しが解決する前に `getTokenizer` を 10 回呼ぶ
- Then: 辞書のファイルは一度だけ読まれ、10 個の Promise はすべて同じトークナイザーで解決する

シナリオ：辞書がすでに読み込まれているとき、後から指定した辞書のパスは使われない

- Given: `getTokenizer` がトークナイザーで解決している
- When: 別の `dicPath` で `getTokenizer` を呼ぶ
- Then: Promise は同じトークナイザーで解決し、別のパスからはファイルを読まない

### 辞書をどこから読み込むかを選ぶ

ブラウザや特別な環境で kuromojin を使う開発者として、辞書がどこにあるかを kuromojin に伝えたい。URL や別のディレクトリから読み込めるようにするためです。

**受け入れ条件：**

シナリオ：ページが辞書の URL をグローバルに設定したとき、すべてのモジュールがそれを使う

- Given: 辞書が読み込まれる前に `window.kuromojin = { dicPath: "https://example.com/dict/kuromojin.dict" }` を設定するページ
- When: そのページのどれかのモジュールが、オプションなしで `getTokenizer` または `tokenize` を呼ぶ
- Then: 辞書は `https://example.com/dict/kuromojin.dict` に要求される

シナリオ：ワーカーが辞書の URL をグローバルに設定したとき、ワーカーのモジュールがそれを使う

- Given: 辞書が読み込まれる前に `globalThis.kuromojin = { dicPath: "https://example.com/dict/kuromojin.dict" }` を設定する Web Worker
- When: そのワーカーのモジュールが、オプションなしで `getTokenizer` を呼ぶ
- Then: 辞書は `https://example.com/dict/kuromojin.dict` に要求される

シナリオ：ブラウザがパッケージの辞書を読み込むとき、1 つのファイルをダウンロードする

- Given: 辞書のパスが、kuromojin のパッケージの `kuromojin.dict` ファイルの URL であるページ
- When: `getTokenizer` を呼ぶ
- Then: ページはその URL を要求し、ほかの辞書のファイルは要求しない。Promise はトークナイザーで解決する

シナリオ：最初の呼び出しに辞書のパスがあるとき、辞書はそこから読み込まれる

- Given: 辞書がまだ読み込まれていない
- When: 辞書のパスで `getTokenizer({ dicPath })` を呼ぶ
- Then: `KUROMOJIN_DIC_PATH` が別の辞書を指していても、辞書はそのパスから読み込まれる

シナリオ：環境変数が設定されているとき、辞書はそこから読み込まれる

- Given: `KUROMOJIN_DIC_PATH` に辞書のパスが設定され、辞書がまだ読み込まれていない
- When: オプションなしで `getTokenizer` を呼ぶ
- Then: 辞書はそのパスから読み込まれる

### kuromoji.js の辞書を使い続ける

ページやプロジェクトで kuromojin に kuromoji.js の辞書を指定している開発者として、その辞書が動き続けてほしい。設定を変えずに kuromojin を更新できるようにするためです。

**受け入れ条件：**

シナリオ：辞書のパスが kuromoji.js の辞書のディレクトリのとき、その辞書が読み込まれる

- Given: 辞書のパスが、12 個の `*.dat.gz` ファイルを持つ kuromoji.js 0.1.2 の `dict` ディレクトリを指し、辞書がまだ読み込まれていない
- When: テキスト `黒文字` で `tokenize` を呼ぶ
- Then: Promise は、パッケージの辞書を使うときと同じトークンで解決する

シナリオ：ブラウザが kuromoji.js の辞書を読み込むとき、その辞書のファイルだけを要求する

- Given: 辞書のパスが、kuromoji.js 0.1.2 の `dict` ディレクトリを配信する URL であるページ
- When: `getTokenizer` を呼ぶ
- Then: ページは 12 個の `*.dat.gz` ファイルを要求し、ほかのファイルは要求しない。Promise はトークナイザーで解決する

### 読み込めない辞書に気づく

開発者として、辞書を読み込めないときは、はっきりした失敗がほしい。パスを直せるようにするためです。

**受け入れ条件：**

シナリオ：辞書のファイルを読めないとき、Promise は読み込みのエラーで拒否される

- Given: `KUROMOJIN_DIC_PATH` に存在しないディレクトリが設定されている
- When: `getTokenizer` を呼ぶ
- Then: Promise は、開けなかったファイルの名前を含むエラーで拒否される

## KPI

### パッケージの辞書のサイズ

- **目標値：** 新しい辞書のバージョンの変更の分を除いて、前のリリースより大きくならない。小さくなることが望ましい。
- **測定方法：** パッケージの `dict` ディレクトリにあるファイルのサイズを、公開される状態で合計する。
- **測定時期：** 辞書またはその形式を変えるとき。

### 辞書を読み込む時間

- **目標値：** 同じマシンで、前のリリースより遅くならない。速くなることが望ましい。
- **測定方法：** 新しいプロセスで、`getTokenizer` の最初の呼び出しから結果が返るまでの時間を数回測定し、前のリリースと変更後の中央値を比べる。
- **測定時期：** 辞書、その形式、または読み込みを変えるとき。

## 機能要件

### 辞書のパスを選ぶ

**概要：** kuromojin は、`getTokenizer` または `tokenize` の最初の呼び出しが読み込みを始めるときに、辞書のパスを決める。

**入力：** その呼び出しの `options`、環境変数 `KUROMOJIN_DIC_PATH`、`globalThis.kuromojin.dicPath`。

**出力：** 辞書を読み込むファイル、ディレクトリ、または URL。

#### 適用条件

次のうち、最初に存在するものを使います。

1. 呼び出しの `options` の `dicPath`
2. 環境変数 `KUROMOJIN_DIC_PATH`
3. `globalThis.kuromojin.dicPath`
4. kuromojin のパッケージの `dict` ディレクトリにある `kuromojin.dict` ファイル（kuromojin が見つけられるとき）

設定されていない指定は飛ばします。そのため、`dicPath` のない `options`（たとえば `noCacheTokenize` だけの `options`）のときは、残りの 3 つから選びます。

3 番目は、環境のグローバルオブジェクトから読みます。そのため、ページ、ワーカー、Node.js のどれでも使えます。
ページではグローバルオブジェクトが `window` なので、`window.kuromojin.dicPath` は同じ設定です。

Node.js では、kuromojin は 4 番目をファイルシステムで見つけます。
Vite や webpack のように `new URL(path, import.meta.url)` に対応したバンドラーでビルドするページでは、バンドラーがファイルをビルドにコピーし、kuromojin はそのコピーの URL を使います。
ページはそのコピーと一緒に配信されるので、ほかのサーバーには接続しません。
それ以外のブラウザの構成、たとえば esbuild のようにこの書き方に対応していないバンドラーや、バンドラーを使わずに kuromojin を読み込むページでは、`options` か `globalThis.kuromojin.dicPath` で辞書のパスを指定しなければなりません。
`dict` ディレクトリは npm パッケージで公開されるので、パッケージのファイルを配信するサーバーにあるそのファイルの URL を、辞書のパスにできます。
このファイルは、パッケージのパス `kuromojin/dict/kuromojin.dict` にあり、このパスは 1 つのメジャーバージョンのどのリリースでも同じです。そのため、バンドラーでビルドするページは、そのファイルの URL をバンドラーから受け取り、辞書のパスとして渡せます。[オンラインのプレイグラウンド](../playground/requirements.ja.md) は、そのようなページです。

#### 例外時の挙動

##### ブラウザで辞書のパスがない

ブラウザで 4 つのどれもないとき、読み込みは [読み込めない辞書](#読み込めない辞書) で説明するとおりに失敗します。

### 辞書を読み込む

**概要：** `getTokenizer` または `tokenize` の最初の呼び出しが辞書を読み込み、その後の呼び出しはすべて読み込み済みの辞書を使う。

**入力：** 辞書のパス。

**出力：** インストールされた kuromojin の同じコピーのすべての呼び出し元が共有するトークナイザー。

#### 適用条件

##### パッケージの辞書

パッケージの辞書は、kuromoji.js 0.1.2 の IPADIC の辞書の単語を、同じ品詞、読み、コストで持ちます。
辞書は kuromojin の形式で保存されています。この形式は、ダウンロードが小さく、読み込みが速くなるように作られています。
この形式の辞書は 1 つのファイルで、パッケージのファイルの名前は `kuromojin.dict` です。
このファイルは、[辞書のバージョン](../dictionary-versions/requirements.ja.md) も含めて辞書のすべてのデータを持ち、形式のバージョンを示します。
`.dict` で終わる辞書のパスは、このようなファイルを指します。

##### kuromoji.js の辞書

`.dict` で終わらない辞書のパスは、kuromoji.js の形式の辞書を持つディレクトリまたは URL を指します。`base.dat.gz`、`check.dat.gz`、`tid.dat.gz`、`tid_pos.dat.gz`、`tid_map.dat.gz`、`cc.dat.gz`、`unk.dat.gz`、`unk_pos.dat.gz`、`unk_map.dat.gz`、`unk_char.dat.gz`、`unk_compat.dat.gz`、`unk_invoke.dat.gz` の 12 個のファイルです。
kuromojin は、辞書のパスの終わりで 2 つの形式を見分けます。そのため、呼び出し元は形式を指定せず、kuromojin はその形式のファイルだけを読みます。
このような辞書は、利用者が kuromoji.js のツールで作った辞書のように、パッケージの辞書とは違う単語を持つことがあります。そのときのトークンは、その辞書に従います。

##### Node.js とブラウザ

Node.js では、辞書を辞書のパスからファイルシステムで読みます。
ブラウザでは、HTTP で要求し、ブラウザが展開します。そのため、ブラウザには `fetch` と [`DecompressionStream`](https://developer.mozilla.org/en-US/docs/Web/API/DecompressionStream) が必要です。

##### インストールされたコピーごとに 1 つの辞書

読み込んだ辞書は、プロセスが終わるまで保持します。
辞書は、インストールされた kuromojin の 1 つのコピーの呼び出し元が共有します。
`node_modules` に kuromojin のコピーが複数あると、それぞれのコピーが自分の辞書を読み込みます。

#### 例外時の挙動

##### 読み込めない辞書

ファイルを読めないとき、その呼び出しの Promise は読み込みのエラーで拒否されます。
パスが `.dict` で終わるファイルが、インストールされた kuromojin の知らない形式のバージョンを示すとき、または kuromojin の辞書ではないとき、Promise はそのことを伝えるエラーで拒否されます。
kuromojin は読み込みをやり直しません。そのプロセスのその後の呼び出しは、別の辞書のパスを指定しても、すべて同じエラーで拒否されます。

## データ要件

### 必要なデータ

- **辞書のファイル：** 品詞、読み、コストを持つ IPADIC の単語。kuromojin は読むだけである。
- **通知：** mecab-ipadic と kuromoji.js の著作権とライセンスの通知。辞書のファイルと一緒に `dict` ディレクトリで公開する。

### 関係

インストールされた kuromojin の 1 つのコピーは、読み込んだ辞書を多くても 1 つ持ちます。

### 個人情報

なし。辞書は kuromojin の利用者についてのデータを含みません。

## 外部サービスへの依存

なし。Node.js では、辞書はインストールされたパッケージから読み込みます。
ブラウザでは、辞書はバンドラーがコピーしたときはページのサーバーから、それ以外はページが選ぶサーバーから読み込みます。kuromojin はサーバーを指定しません。

## セキュリティの考慮事項

辞書は解析の結果を決めるので、呼び出し元が信頼する場所から読み込まなければなりません。
ブラウザでは、辞書へのリクエストによって、ページが kuromojin を使っていることがサーバーに伝わります。解析するテキストは送られません。

## 未解決事項

- **読みを持たない辞書：** `reading` と `pronunciation` を持たない辞書はより小さくなるが、パターンで読みを指定するルールは、エラーを出さずに検出しなくなる。決めるまでは、パッケージの辞書はすべての単語でこの 2 つの項目を持つ。textlint-rule-preset-ja-technical-writing のルールがパターンで読みを指定しなくなったときに見直す。azu が決める。
