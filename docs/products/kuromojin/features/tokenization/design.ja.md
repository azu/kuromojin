# トークン化の設計

[English](design.md)

## この文書について

この設計は、kuromojin が [kuromojin の Product](../../product.ja.md) の [トークン化の Requirements](requirements.ja.md) をどう満たすかを説明します。

### 読者

kuromojin の解析やトークンの再利用を変更する人とエージェント。

### 前提知識

- [トークン化の Requirements](requirements.ja.md)。特にトークンの項目と基準の結果
- [辞書の Requirements](../dictionary/requirements.ja.md)。トークナイザーが何から作られるか

### この文書の範囲外

辞書をどう見つけ、読み込み、ファイルに保存するか、およびオンラインのプレイグラウンド。

## 実装の方針

kuromojin は、自分のトークナイザーでテキストを解析します。トークナイザーは TypeScript で書かれ、kuromoji.js から派生したものです。
トークナイザーは、テキストを辞書の単語に分けるすべての方法の中から、コストの合計がもっとも低いものを見つけます。
`tokenize` は、その手前にトークンのキャッシュを置きます。

以下は 1 回の解析の順に説明します。トークナイザーが辞書から受け取るデータ、候補、もっともよい分け方の選択、トークンの順です。
トークンの再利用は最後に説明します。

### 辞書から受け取るデータ

トークナイザーは 4 種類のデータを必要とし、読み込んだ辞書からいくつかの問い合わせで受け取ります。

- **単語：** テキストのある位置について、そこから始まる辞書の単語。トライが、テキストを 1 回たどるだけで答える。
- **エントリー：** ある単語について、そのエントリー。同じ表記が、名詞と動詞のように複数のエントリーを持つことがある。各エントリーは左 ID、右 ID、単語のコストを持つ。
- **連接コスト：** あるエントリーの右 ID と次のエントリーの左 ID について、その 2 つを並べるコスト。
- **未知語：** ある文字について、ひらがな、アルファベット、数字などの文字の種類と、その種類の未知語が使えるエントリー。

トークナイザーは、作られるときに ID とコストを数値の配列にコピーします。そのため、解析は配列だけを読みます。
品詞や読みなど、エントリーのそのほかの項目は、選ばれた分け方の単語についてだけ読みます。

### 候補

トークナイザーはテキストを先頭からたどり、候補を集めます。候補とは、それぞれの位置から始まることができる単語です。
ある位置を使うのは、そこで終わる候補があるときだけです。それ以外の位置からは、分け方を続けられないためです。

使える位置では、そこから始まる辞書のすべての単語のエントリーが候補になります。
未知語を加えるのは、そこから始まる辞書の単語がないときと、文字の種類が常に未知語を求めるときです。
未知語の長さは文字の種類で決まります。まとめる種類では同じ種類の文字が続く範囲の全体になり、それ以外の種類では 1 文字になります。

候補が、サロゲートペアの 2 つの部分の間で始まったり終わったりすることはありません。
ペアの種類は既定の種類で、これはまとめる種類なので、ペアが続く範囲は 1 つの未知語になります。
ペアのないサロゲートは 1 文字です。上位のサロゲートは既定の種類で、下位のサロゲートは辞書がそのコードに与える種類です。これは基準の結果と同じ扱いです。
U+0000 は、辞書がそれに与える種類を持つ文字で、単語の問い合わせでは、どの単語にも含まれない文字として扱います。

### もっともよい分け方の選択

分け方のコストは、そのエントリーの単語のコストと、隣どうしの連接コストの合計です。テキストの先頭と末尾との連接も含みます。
トークナイザーは候補ごとに、その候補で終わる分け方のもっとも低いコストと、その分け方での 1 つ前の候補を保持します。
この 2 つは、候補を加えるときに、新しい候補が始まる位置で終わる候補から計算します。
最後の位置まで進んだら、テキストの末尾で終わるもっともよい候補を選び、リンクを先頭までたどります。

2 つの分け方のコストが同じときは、先に加えた候補が選ばれます。
候補を加える順序は決まっています。始まる位置の順、辞書の単語が未知語より先、短い単語が長い単語より先、同じ単語のエントリーは辞書の順です。
この順序は結果の一部です。コストが等しいテキストのトークンを決めるためです。

### 1 回の解析のメモリ

候補はオブジェクトではなく、表の行です。
表の各列は数値の配列です。エントリー、始まり、終わり、右 ID、1 つ前の候補、もっとも低いコスト、同じ位置で終わる次の候補の列があります。
トークナイザーは呼び出しの間も配列を保持し、テキストがより多くの行を必要とするときに配列を大きくします。
決まった数より多くの行を持つ配列を、大きな配列と呼びます。トークナイザーは、長いテキストが続く間は大きな配列を保持し、大きな配列を必要としない解析が 100 回続くと、最初の大きさの配列に戻します。
そのため、長い 1 つのテキストのメモリをプロセスが終わるまで保持することはなく、長いテキストが続くときにテキストごとに配列を作り直すこともありません。
そのため、解析がオブジェクトを作るのは、返すトークンの分だけです。

トークナイザーは同期で動き、JavaScript は一度に 1 つの呼び出ししか実行しないので、呼び出しの間で配列を共有しても安全です。

### トークン

トークナイザーは、選ばれた分け方の候補ごとに 1 つのトークンを作ります。
`surface_form` は、テキストのうち候補の始まりから終わりまでの部分です。
そのほかの項目はエントリーから取ります。未知語のトークンには `reading` と `pronunciation` を付けません。
`word_position` は、文字で数えた始まりに 1 を足した値で、その単語より前のサロゲートペアは 1 と数えます。

`tokenizeForSentence` は、この手順をテキスト全体に対して実行します。
トークナイザーの `tokenize` は、`、` と `。` の後ろでテキストを分け、それぞれに手順を実行し、`word_position` を前の部分から続けて数えます。

### トークンの再利用

`tokenize(text, options)` は、まずトークナイザーを待ちます。
次に、テキストをマップで探します。テキストの値は、そのテキストを解析した辞書のバージョンごとのトークンを持ちます。
呼び出しの辞書のバージョンのトークンがあれば、保存してある配列を返します。
なければ、そのバージョンのトークナイザーの `tokenizeForSentence(text)` を呼び、返った配列をそのテキストとバージョンのものとして保存し、その配列を返します。
`noCacheTokenize: true` のときは、`tokenizeForSentence(text)` を呼び、マップを読み書きせずに結果を返します。

マップのキーは、呼び出し元が渡したテキストそのものです。そのため、探すときに文字列を作りません。
マップは最近使われた 10,000 個のテキストを保持し、いっぱいになると、もっとも長く使われていないテキストを、すべてのバージョンのトークンと一緒に取り除きます。
マップはモジュールの変数なので、インストールされた kuromojin のコピーごとに 1 つあり、1 つのコピーのすべての呼び出し元が共有します。
保存した配列はコピーも凍結もしません。呼び出し元による変更を防いでいるのは、結果の読み取り専用の型です。

## アーキテクチャとシーケンス図

図は不要です。解析は、テキストを 1 回たどり、選ばれた分け方を 1 回さかのぼるだけです。`tokenize` は、その手前でマップを 1 回引きます。

## データモデルと ER 図

トークンは、[トークンの項目](requirements.ja.md#トークンの項目) で説明するオブジェクトです。
キャッシュは 1 つのマップで、キーがテキスト、値がそのテキストのトークンの配列です。配列は、テキストを解析した辞書のバージョンごとに 1 つあります。
候補の表は 1 回の解析の間だけ意味を持ち、[1 回の解析のメモリ](#1-回の解析のメモリ) で説明します。

## API とインターフェース

kuromojin は 2 つの関数と 4 つの型を公開します。

- `tokenize(text: string, options?: getTokenizerOption): Promise<Readonly<Readonly<KuromojiToken>[]>>`
- `getTokenizer(options?: getTokenizerOption): Promise<Tokenizer>`
- `KuromojiToken` はトークンの型である。未知語のトークンは `reading` と `pronunciation` を持たないが、型はこの 2 つを `string` と宣言する。
- `Tokenizer` は `tokenize(text: string): KuromojiToken[]` と `tokenizeForSentence(text: string): KuromojiToken[]` を持つ。
- `getTokenizerOption` は、どれも省略できる `dicPath?: string`、`dictionaryVersion?: DictionaryVersion`、`noCacheTokenize?: boolean` を持つ。
- `DictionaryVersion` は `dictionaryVersion` の値の型である。パッケージの辞書が持つバージョンの日付のユニオン型である。

## 外部サービスとの連携

なし。解析は kuromojin の一部で、ネットワークのサービスを使いません。キャッシュは npm パッケージ `lru_map` に依存します。

## データの扱い

テキストとそのトークンは、上で説明したマップだけに、プロセスのメモリの中で保持します。
候補の表は、最後に解析したテキストについての数値を、次の解析が上書きするまで保持します。
ファイルには何も書きません。

## 認証と認可の注意

なし。解析にアクセス制御はありません。

## セキュリティの考慮事項

[Requirements のセキュリティの考慮事項](requirements.ja.md#セキュリティの考慮事項) のほかにはありません。共有されるトークンを変更する呼び出し元に対して、この設計は保護を加えません。

解析の時間とメモリはテキストの長さとともに増え、トークナイザーは長さに上限を設けません。

## デプロイの注意

どれかのテキストのトークンを変える変更は、kuromojin のメジャーバージョンとしてリリースします。トークンをパターンと比べるルールが、トークンに依存しているためです。
テキストの文字が欠けたり壊れたりする不具合の修正は、バグ修正としてリリースし、影響するテキストをリリースノートに書きます。

トークナイザーのソースは、Apache License 2.0 でライセンスされた kuromoji.js から派生しています。
kuromoji.js の辞書で単語を探す部分は、MIT License でライセンスされた doublearray から派生しています。
パッケージは、ライセンスを次のように示します。

- リポジトリの `LICENSE` ファイルは、kuromojin の MIT License だけを持つ。このファイルからリポジトリのライセンスを読むツールが、1 つのライセンスを見つけられるようにするためである。
- `package.json` の `license` フィールドは `MIT AND Apache-2.0` である。
- README は、パッケージのどの部分がどのライセンスかを示す節を持つ。

## 検討した代替案

### kuromoji.js を依存として使う

kuromojin が `kuromoji` パッケージのトークナイザーを呼び続ける方法です。
採用しませんでした。時間とサイズの大部分は解析と辞書の形式にあり、どちらもパッケージの外からは変更できないためです。

### 候補をオブジェクトとして持つ

候補を 1 つずつオブジェクトにして、参照でつなぐ方法です。
採用しませんでした。テキストの候補はトークンよりずっと多く、候補ごとにオブジェクトを作って回収することが、解析の時間の大きな部分を占めるためです。

### WebAssembly にコンパイルした解析器を使う

別の解析器でトークナイザーを置き換える方法です。
採用しませんでした。トークンが基準の結果と異なり、トークンをパターンと比べるすべてのルールを書き直す必要があるためです。

### 解析の前に句読点でテキストを分ける

トークナイザーの `tokenize` のように、`tokenize` が `、` と `。` でテキストを分け、それぞれを解析する方法です。
採用しませんでした。`。` で強制的に分けると誤った結果になったためです。

### そのほかの判断

キャッシュの大きさと `lru_map` の選択については、代替案の記録がなく、理由はわかっていません。
