# トークン化

[English](requirements.md)

## この文書について

トークン化は、日本語のテキストのトークンを返します。
呼び出し元は、`tokenize(text)` を 1 回呼んでトークンを受け取るか、`getTokenizer()` でトークナイザーを受け取ってテキストを同期的に解析します。
`tokenize(text)` とトークナイザーはテキストごとのトークンも覚えておくので、同じテキストを求める呼び出し元は 1 回の解析を共有します。
親の Product は [kuromojin](../../product.ja.md) です。

### 範囲

- `tokenize` 関数と、`getTokenizer` が返すトークナイザー
- トークンの項目
- トークンがどの結果と等しくなければならないか、どれだけの間同じであるか
- テキストのトークンの再利用
- 解析の速さ

### 範囲外

- 辞書をどこから見つけ、どう読み込むか。[辞書](../dictionary/requirements.ja.md) を参照
- トークンをパターンと比べること、文書を文に分けること。ルールがほかのパッケージで行う
- 選ばれなかった候補など、解析の内部を見ること。トークナイザーはトークンだけを返す
- IPADIC 以外の辞書と、利用者が追加する単語

## ユーザーストーリー

### 1 回の呼び出しでテキストのトークンを得る

ルール作者として、関数を 1 回呼ぶだけでテキストのトークンを受け取りたい。ルールが辞書やトークナイザーを扱わずに済むようにするためです。

**受け入れ条件：**

シナリオ：テキストをトークン化すると、各単語が項目を持つトークンになる

- Given: テキスト `黒文字`
- When: そのテキストで `tokenize` を呼ぶ
- Then: Promise は 1 つのトークンで解決する。その `surface_form` は `黒文字`、`pos` は `名詞`、`basic_form` は `黒文字`、`reading` は `クロモジ`、`word_type` は `KNOWN`、`word_position` は 1 である

シナリオ：テキストに複数の文があるとき、位置はテキストの先頭から数える

- Given: テキスト `これは1文。これは2文。`
- When: そのテキストで `tokenize` を呼ぶ
- Then: 最初のトークンの `word_position` は 1 で、最後のトークンである 2 つ目の `。` の `word_position` は 12 である

シナリオ：単語が辞書にないとき、未知語のトークンになる

- Given: テキスト `Fooをする`
- When: そのテキストで `tokenize` を呼ぶ
- Then: 最初のトークンは `surface_form` が `Foo`、`word_type` が `UNKNOWN`、`pos` が `名詞`、`basic_form` が `*` で、`reading` と `pronunciation` を持たない

シナリオ：テキストが空のとき、トークンはない

- Given: 空のテキスト
- When: そのテキストで `tokenize` を呼ぶ
- Then: Promise は空の配列で解決する

シナリオ：テキストに基本多言語面の外の文字があるとき、すべての文字がトークンに含まれる

- Given: テキスト `𩸽𩸽を食べた`
- When: そのテキストで `tokenize` を呼ぶ
- Then: トークンは `𩸽𩸽`、`を`、`食べ`、`た` で、`word_position` は 1、3、4、6 である

### どんなテキストも失敗せずに解析する

ほかの人が書いたファイルをチェックする書き手として、どんなテキストも解析してほしい。変わった文字が textlint の実行を止めないようにするためです。

**受け入れ条件：**

シナリオ：テキストに NUL 文字があるとき、その文字は未知語になる

- Given: `a`、U+0000、`b` の 3 文字からなるテキスト
- When: そのテキストで `tokenize` を呼ぶ
- Then: Promise は 3 つのトークンで解決し、2 つ目は `surface_form` が U+0000 で、`word_type` が `UNKNOWN` である

シナリオ：テキストにペアのないサロゲートがあるとき、そのサロゲートは未知語になる

- Given: `あ`、単独の上位サロゲート U+D83D、`い` の 3 文字からなるテキスト
- When: そのテキストで `tokenize` を呼ぶ
- Then: Promise は 3 つのトークンで解決し、2 つ目は `surface_form` が U+D83D で、`word_type` が `UNKNOWN` である

### 解析をほかのルールと共有する

多くの日本語のルールを実行する書き手として、1 つの文は一度だけ解析してほしい。ルールごとに同じ解析を繰り返さないようにするためです。

**受け入れ条件：**

シナリオ：同じテキストをもう一度トークン化すると、解析せずに同じトークンが返る

- Given: `tokenize` がすでに解析したテキスト
- When: 同じテキストで `tokenize` を呼ぶ
- Then: Promise は最初の呼び出しと同じ配列で解決する

シナリオ：キャッシュを切ると、テキストはもう一度解析される

- Given: `tokenize` がすでに解析したテキスト
- When: 同じテキストと `noCacheTokenize: true` で `tokenize` を呼ぶ
- Then: Promise は等しいトークンを持つ新しい配列で解決し、覚えているトークンは変わらない

### テキストを同期的に解析する

多くのテキストをループで解析する開発者として、トークナイザーそのものを受け取りたい。解析のたびに Promise を経由しないようにするためです。

**受け入れ条件：**

シナリオ：トークナイザーでテキストを解析すると、トークンが直接返る

- Given: `getTokenizer` が解決したトークナイザー
- When: テキスト `黒文字` で `tokenizeForSentence` を呼ぶ
- Then: kuromojin の `tokenize` と同じ配列が返る

シナリオ：トークナイザーで同じテキストをもう一度解析すると、解析せずに同じトークンが返る

- Given: トークナイザーの `tokenizeForSentence` か `tokenize` で解析済みのテキスト
- When: 同じ関数を同じテキストで呼ぶ
- Then: 最初の呼び出しと同じ配列が返る

シナリオ：キャッシュを切ると、トークナイザーはどのテキストももう一度解析する

- Given: `noCacheTokenize: true` で `getTokenizer` が解決したトークナイザー
- When: 同じテキストで `tokenizeForSentence` を 2 回呼ぶ
- Then: それぞれの呼び出しは等しいトークンを持つ新しい配列を返し、覚えているトークンは変わらない

## KPI

### 基準の結果と同じトークン

- **目標値：** 比較するすべてのテキストで、トークンのすべての項目が [基準の結果](#基準の結果) と等しい。
- **測定方法：** 実際の日本語の文書の文とランダムな文字列を、kuromojin と kuromoji.js 0.1.2 で解析し、トークンを比べる。基準が文字を失うテキストと、基準が失敗するテキストは、この文書が説明する挙動と比べる。
- **測定時期：** 解析器または辞書の形式を変えるとき。

### 解析の速さ

- **目標値：** 同じテキストで、前のリリースより遅くならない。速くなることが望ましい。
- **測定方法：** 実際の日本語の文書の文を、トークンを再利用せずにループで解析し、前のリリースと変更後の中央値を比べる。
- **測定時期：** 解析器または辞書の形式を変えるとき。

### 日本語のルールを使う textlint の実行時間

- **目標値：** textlint-rule-preset-ja-technical-writing を使う textlint の実行が、kuromojin 3.0.2 と textlint 16.1.1 での同じ実行の 20% 以下の時間で終わる。
- **測定方法：** 測定するリリースと最新の textlint の組み合わせと、基準の 2 つのバージョンの組み合わせで、多くの日本語の文書を同じマシンでチェックする。2 つを交互に実行し、中央値を比べる。
- **測定時期：** 解析器または辞書の形式を変更するリリースの前。

## 機能要件

### テキストをトークン化する

**概要：** `tokenize(text, options)` はテキストのトークンを返す。

**入力：** 文字列と、省略できる `options`。`noCacheTokenize: true` は、その呼び出しでトークンの再利用を切る。`dicPath` は [辞書](../dictionary/requirements.ja.md) で、`dictionaryVersion` は [辞書のバージョン](../dictionary-versions/requirements.ja.md) で説明する。

**出力：** テキストの順に並んだ、読み取り専用のトークンの配列の Promise。

#### 適用条件

##### トークンの項目

| 項目 | 意味 |
| --- | --- |
| `word_id` | 辞書の中での単語の識別子 |
| `word_type` | 辞書にある単語は `KNOWN`、未知語は `UNKNOWN` |
| `word_position` | テキストの中での単語の最初の文字の位置。テキストの最初の文字が 1 |
| `surface_form` | テキストに書かれたとおりの単語 |
| `pos` | 品詞。`名詞`、`助詞` など |
| `pos_detail_1`、`pos_detail_2`、`pos_detail_3` | 品詞の細分類。ないときは `*` |
| `conjugated_type` | 活用型。活用しない単語は `*` |
| `conjugated_form` | 活用形。活用しない単語は `*` |
| `basic_form` | 原形。未知語は `*` |
| `reading` | カタカナの読み。未知語のトークンはこの項目を持たない |
| `pronunciation` | カタカナの発音。未知語のトークンはこの項目を持たない |

`word_position` は文字を数え、サロゲートペアは 1 文字と数えます。
そのため、`word_position - 1` が JavaScript の文字列のインデックスになるのは、その単語より前にサロゲートペアがないときだけです。

トークンの `surface_form` を順につなぐと、テキストになります。

##### 基準の結果

テキストの基準の結果は、kuromoji.js 0.1.2 が同じ辞書でそのテキストに返す結果です。
既存のルールは、この結果に合わせて書かれています。
kuromojin は基準と同じトークンを返し、すべての項目の値も同じです。
違うのは、基準が文字を失うテキストと、基準が失敗するテキストだけです。これらは [基本多言語面の外の文字](#基本多言語面の外の文字) と [どの単語にも含まれない文字](#どの単語にも含まれない文字) で説明します。

`tokenize` はテキスト全体をひとまとまりとして解析します。
解析の前に `、` や `。` でテキストを分けません。分けると誤った結果になったためです。

##### 安定性

パッケージに含まれる辞書を同じ辞書のバージョンで使うとき、テキストのトークンは、kuromojin の 1 つのメジャーバージョンのどのリリースでも同じです。
それでも、トークンから文字が欠けるといった解析の不具合は、リリースで修正できます。そのような修正はバグ修正であり、リリースノートが、どのテキストに影響するかを示します。

##### 基本多言語面の外の文字

`𩸽` や絵文字のような基本多言語面の外の文字は、JavaScript の文字列ではサロゲートペアです。
kuromojin はペアを 1 文字として扱います。ペアが 2 つのトークンに分かれることはなく、`word_position` では 1 と数えます。
このような文字は、辞書にないほかの文字と同じように未知語になり、その後ろの単語はいつもどおり解析されます。

##### どの単語にも含まれない文字

U+0000 とペアのないサロゲートは、ほかの文字と同じ 1 つの文字です。
辞書のどの単語もこれらを含まないので、それぞれが未知語か、未知語の一部になります。
そのため、どんな文字列にもトークンがあり、テキストが原因で `tokenize` が拒否されることはありません。

##### トークンの再利用

`tokenize` は、最近使われた 1,000 個のテキストのトークンを覚えています。
キーはテキストとその呼び出しの辞書のバージョンで、`dicPath` が何であっても覚えているトークンを使います。
返す配列とそのトークンはすべての呼び出し元で共有されるので、呼び出し元は変更してはなりません。結果の型が読み取り専用なのはこのためです。

#### 例外時の挙動

##### 読み込めない辞書

Promise は拒否されます。[辞書](../dictionary/requirements.ja.md) を参照してください。

### トークナイザーを得る

**概要：** `getTokenizer(options)` は、辞書を読み込んだ後のトークナイザーを返す。

**入力：** 省略できる `options`。`dicPath`、`dictionaryVersion`、`noCacheTokenize` を持つ。`noCacheTokenize: true` は、トークンを再利用しないトークナイザーを求める。[辞書](../dictionary/requirements.ja.md) と [辞書のバージョン](../dictionary-versions/requirements.ja.md) を参照。

**出力：** トークナイザーの Promise。同じ辞書のバージョンと同じ `noCacheTokenize` の呼び出しは、どれも同じトークナイザーで解決する。

#### 適用条件

トークナイザーは、テキストを受け取ってトークンの配列を返す同期の関数を 2 つ持ちます。
トークナイザーは、このほかに公開するメンバーを持ちません。

- `tokenizeForSentence(text)` はテキスト全体をひとまとまりとして解析する。覚えているトークンを kuromojin の `tokenize` と共有するので、どちらかが解析したテキストを、もう一方がもう一度解析することはない。
- `tokenize(text)` は非推奨である。kuromoji.js のトークナイザーの `tokenize` に向けて書かれたコードのためにあり、その型は非推奨であることをエディターに伝える。`、` と `。` の後ろでテキストを分け、それぞれを解析し、すべてのトークンを順に返す。そのトークンはテキスト全体のトークンと異なるので、`tokenizeForSentence` とは別に、こちらも最近使われた 1,000 個のテキストのトークンを覚える。

どちらの関数も、kuromojin の `tokenize` と同じく、テキストと辞書のバージョンについて覚えている配列を返し、結果の型は読み取り専用です。
`noCacheTokenize: true` のときは、どのテキストももう一度解析して新しい配列を返し、覚えているトークンを読みも変えもしません。

#### 例外時の挙動

なし。トークナイザーは辞書を読み込んだ後にだけ存在し、その関数はどんな文字列にもトークンを返します。

## データ要件

### 必要なデータ

- **テキスト：** 解析する文字列。`tokenize` とトークナイザーは、覚えているトークンのキーとしてメモリに保持する。プロセスが終わるか、より新しい 1,000 個のテキストに置き換えられるまで保持する。トークナイザーの `tokenize` のテキストは、ほかとは別に数える。ファイルには書かず、どこにも送らない。
- **トークン：** 解析の結果。テキストと一緒にメモリに保持する。
- **辞書：** 解析が使うデータ。[辞書](../dictionary/requirements.ja.md) を参照。

### 関係

1 つのテキストと 1 つの辞書のバージョンの組は、テキスト全体のトークンの配列を 1 つと、トークナイザーの `tokenize` で分けたトークンの配列を 1 つ持ちます。

### 個人情報

kuromojin は個人情報を集めません。
呼び出し元が渡すテキストには個人情報が含まれることがあり、上のとおりプロセスのメモリに残ります。

## 外部サービスへの依存

なし。解析は呼び出し元のプロセスの中で動きます。

## セキュリティの考慮事項

テキストとトークンは呼び出し元のプロセスの中にとどまります。
覚えているトークンはプロセスの中で共有されるので、それを変更した呼び出し元は、ほかのすべての呼び出し元の結果を変えてしまいます。

## 未解決事項

- **少ない文書での textlint の実行時間の目標：** 文書が少ないと、textlint の起動とルールそのものが時間の大部分を占めるので、20% という目標は kuromojin だけでは届かないことがある。決めるまでは、目標は数千の文書に適用し、少ない文書は測定して目標なしで報告する。kuromojin の解析器を使う最初のリリースを測定したときに見直す。azu が決める。
- **`word_id` の値：** `word_id` は基準の結果と同じ値である。単語に新しい番号を付ければ辞書は小さくなり、`word_id` を読むルールは知られていない。決めるまでは、値を同じままにする。辞書のサイズをさらに減らすときに見直す。azu が決める。
- **サロゲートペアの後ろの `word_position`：** `word_position` は、基準の結果と同じく、サロゲートペアを 1 文字と数える。そのため、そのような文字の後ろでは JavaScript の文字列のインデックスにならない。決めるまでは、数え方をそのままにし、インデックスが必要なルールは `surface_form` の長さを足して求める。絵文字を含むテキストで位置が誤っているとルールから報告されたときに見直す。azu が決める。
