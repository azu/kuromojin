# kuromojin

[English](product.md)

## 概要

kuromojin は JavaScript のための日本語の形態素解析器です。
日本語のテキストをトークンに分けます。各トークンは、書かれたとおりの単語、品詞、原形、読みを持ちます。
解析そのものは [kuromoji.js](https://github.com/takuyaa/kuromoji.js) が行い、kuromojin はそれを多くの呼び出し元から使いやすくするラッパーです。
呼び出し元は、Promise を返す関数を 1 回呼ぶだけで、テキストのトークンを受け取れます。
kuromojin は辞書を一度だけ読み込み、テキストごとのトークンを覚えておくので、同じプロセスの呼び出し元はその両方を共有します。

呼び出し元の多くは、日本語向けの textlint ルールです。
textlint の 1 回の実行では多くのルールが動き、それぞれのルールが同じ文のトークンを求めます。

## 背景と課題

### 背景

日本語は単語の間に空白を入れずに書きます。
「1 つの文に同じ助詞が 2 回出てくる」といったチェックをするには、まず各単語がどこから始まり、品詞が何であるかを知る必要があります。
形態素解析は、単語の辞書を使ってこれに答えます。この辞書は大きなデータです。

kuromoji.js は JavaScript で書かれた形態素解析器です。
その API はコールバックでトークナイザーを作り、作るたびに辞書を読み込みます。

### 解決する課題

ルール作者は、辞書やコールバックを自分で扱わずに、テキストのトークンを受け取りたいと考えています。

ルールごとに辞書を読み込み、同じ文を何度も解析すると、textlint の実行は遅くなり、メモリも多く使います。
この処理は、1 回の実行の中でルールどうしが共有する必要があります。

ルールは、「ある助詞の後にある動詞が続く」といったパターンとトークンを比べます。
テキストのトークンが変わると、ルールはエラーを出さずに検出しなくなります。
つまり、ルールは解析の結果そのものに依存しているので、結果は安定していなければなりません。

## 対象ユーザー

### ルール作者

- **特徴：** 日本語向けの textlint ルールを npm パッケージとして公開する開発者。
- **課題：** ルールには文のトークンが必要で、同じトークンを必要とするほかの多くのルールと一緒に動く。
- **利用場面：** ルールの中で kuromojin を呼び、[morpheme-match](https://github.com/azu/morpheme-match) などを使ってトークンをパターンと比べる。

### 日本語のルールを実行する書き手

- **特徴：** textlint で日本語の文書をチェックする人。kuromojin を自分では呼ばない。
- **課題：** textlint の実行の時間、メモリ、インストールのサイズには、kuromojin の分が含まれる。
- **利用場面：** コマンドライン、CI、エディタ、ブラウザで textlint を実行する。

### ほかのツールの開発者

- **特徴：** テキストの分析やコマンドラインツールなどのために、Node.js やブラウザで日本語のテキストの単語を必要とする開発者。
- **課題：** トークナイザーを自分で組み立てずに、トークンを受け取りたい。
- **利用場面：** kuromojin をモジュールとして呼ぶ。

## 提供する価値

### 1 回の呼び出しで得られるトークン

- **受け取る人：** ルール作者とほかのツールの開発者
- **提供するもの：** テキストを受け取り、そのトークンの Promise を返す関数。呼び出し元はトークナイザーを作らず、コールバックも渡さない。
- **理由：** ルールが必要とするのはトークンだけで、解析器のライフサイクルではない。

### すべてのルールで 1 つの辞書と 1 回の解析

- **受け取る人：** 日本語のルールを実行する書き手
- **提供するもの：** 辞書はプロセスごとに一度だけ読み込まれ、ほかのルールが同じテキストを求めたときは、そのテキストのトークンが再利用される。
- **理由：** 辞書の読み込みとテキストの解析はコストが高く、1 回の実行のルールは同じ文を求める。

## 主要な概念

- **トークン：** 解析の結果に含まれる 1 つの単語。`surface_form`、`pos`、`basic_form`、`reading` などの項目を持つ。
- **既知語と未知語：** 既知語は辞書にある単語。未知語は、新しい名前のように、辞書にないテキストの一部。トークンは `word_type` でどちらであるかを示す。
- **辞書：** 解析に必要なデータ。品詞と読みを持つ単語と、テキストのどの分け方がもっとも自然かを決めるコストからなる。[mecab-ipadic](https://taku910.github.io/mecab/)（IPADIC）から作られている。
- **トークナイザー：** 辞書を読み込んだ後、テキストを同期的に解析するオブジェクト。
- **辞書のパス：** 辞書のファイルを読み込むディレクトリまたは URL。

## 開発方針

- **すべての呼び出し元で 1 つのコピー。** 辞書とキャッシュは、インストールされた kuromojin のコピーごとに持つ。そのため kuromojin は、1 つだけインストールされるように作る。解析器を厳密なバージョンに固定し、辞書はそのバージョンに付いてくる。
- **Node.js とブラウザで動く。** 同じ API がどちらでも動く。違うのは辞書の場所だけである。
